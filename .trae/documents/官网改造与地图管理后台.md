# 官网改造与地图管理后台实施计划

## Context

现有官网位于 `web/`（Next.js 16 App Router + React 19），是纯英文落地页，下载地址在请求时实时读取 GitHub Release，没有数据库、没有地图列表、没有后台，部署目标是 Vercel。需求是把首页改造成**响应式软件界面**风格的单款魔兽争霸官网：游戏介绍与下载、地图介绍与列表下载、管理后台（游戏下载地址、联系信息、地图数据）、SQLite 存储、阿里云 OSS 直传，并支持中英文与后续低成本增加语言。运行目标改为本地/自有服务器（Node + SQLite 文件）。

## 已确认需求

- 改造 `web/` 官网，不保留旧的英文单页结构。
- 本地/自有服务器运行：`next build && next start`，SQLite 文件持久化。
- 地图/封面上传到阿里云 OSS，数据库只存 URL 和 object key。
- 默认中文，提供英文；语言由 URL 前缀决定，新增语言只需加词典 + 后台启用。
- 管理后台使用中文。

## 技术决策

| 事项 | 决策 | 理由 |
|---|---|---|
| SQLite 驱动 | Node 内置 `node:sqlite`（`DatabaseSync`） | Node 26 本机可用，零原生编译；Next 16/Turbopack 自动 externalize `node:` 内置模块；自有服务器固定 Node ≥24 即可 |
| 数据访问层 | `web/lib/db/index.ts` 单例（挂 `globalThis`）+ WAL/busy_timeout | 避免 HMR 与每请求重复打开；单进程 `next start` 最稳，不支持 PM2 cluster |
| 多语言 | 自研轻量方案（词典模块 + `[locale]` 路由 + cookie 偏好） | 加语言 = 新增词典文件 + `i18n/config.ts` 注册一行 + 后台启用；无需引入 next-intl 的 ICU 复杂度 |
| 文件上传 | 浏览器用服务端签发的 OSS 预签名 URL **直传**，再提交 key/url/size | 绕开 Server Action 1MB 限制，避免大 w3x 进内存/占用 Node 进程 |
| 后台鉴权 | `ADMIN_PASSWORD` + HMAC 签名的 HttpOnly cookie，无会话表 | 单管理员场景足够；改 `ADMIN_SECRET` 即全端下线 |
| 下载地址 | 数据库优先，GitHub Release 作为兜底 | 保留现有 `lib/github.ts` 的 star 数与自动兜底能力 |
| 包管理 | 使用 npm（本机无 pnpm/corepack），生成 `web/package-lock.json` | 当前环境只有 npm 11；部署文档同步改为 npm |

## 数据库 Schema

```sql
settings(key TEXT PRIMARY KEY, value TEXT NOT NULL /* JSON */, updated_at TEXT NOT NULL);

locales(code TEXT PRIMARY KEY, label TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1, sort INTEGER NOT NULL DEFAULT 0);

downloads(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  platform TEXT NOT NULL,          -- windows | linux | macos | other
  label TEXT,                      -- 可选覆盖显示名
  version TEXT, size INTEGER, format TEXT,
  url TEXT NOT NULL, oss_key TEXT,
  enabled INTEGER NOT NULL DEFAULT 1, sort INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL
);

maps(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  slug TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'draft',   -- draft | published
  cover_url TEXT, cover_key TEXT,
  file_url TEXT, file_key TEXT, file_size INTEGER,
  version TEXT, author TEXT, players TEXT,
  sort INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE INDEX idx_maps_status_sort ON maps(status, sort);

map_translations(
  map_id INTEGER NOT NULL REFERENCES maps(id) ON DELETE CASCADE,
  locale TEXT NOT NULL,
  name TEXT NOT NULL DEFAULT '',
  description TEXT NOT NULL DEFAULT '',
  PRIMARY KEY(map_id, locale)
);
CREATE INDEX idx_map_translations_locale ON map_translations(locale);
```

- 联系信息存 `settings.contact`（JSON：email、qqGroup、wechat、github、discord、note），语言中立；界面标签来自词典。
- 迁移：`PRAGMA user_version` + `CREATE TABLE IF NOT EXISTS`，`scripts/migrate.mjs` 可重复执行。
- Seed（幂等）：① GitHub 最新 release 的 AppImage/exe/dmg 写入 downloads；② 读取 `Warcraft III zhCN/Maps/hhkj/*.w3x.zhCN.json` 的 `info.name/description/recommendedPlayers`，以文件名 slugify，写入 `locale=zh` 的 map_translations，en 先留空等待后台补。地图文件本身不复制，后台后续上传 OSS。

## 多语言方案

- `i18n/config.ts` 维护 `LOCALES`（`zh`/`en`，可继续加）、`defaultLocale = "zh"`、`getDict(locale)` 动态 import 词典。
- `zh.ts` 为基准导出 `Messages` 类型，`en.ts` 标注 `: Messages`，漏键编译报错。
- 前台路径统一 `/zh/...`、`/en/...`；`proxy.ts` 将 `/` 重定向到默认语言，校验非法 locale 后回落；切换语言保留当前路径，并写 `ow3_locale` cookie。
- 地图字段回退链：当前语言 → 默认语言 → 空。后台地图编辑页使用语言标签页维护各语言名称/介绍，新增语言后自动出现新标签。
- `generateMetadata` 输出 canonical 与 `alternates.languages`（含 `x-default`）；`sitemap.ts` 遍历已发布地图 × 启用语言。
- 后台界面固定中文，不参与多语言。

## 页面与 UI

- `AppShell`：CSS Grid 的“软件窗口”结构 —— 顶栏（Logo、主导航、语言切换、GitHub Star）+ 左侧导航（首页/下载/地图/联系）+ 可滚动内容区；≤900px 侧栏折叠为抽屉，卡片网格 `repeat(auto-fill, minmax(260px, 1fr))`。
- 复用 `@warcraft-open/ui`：`GlueButton`（下载按钮）、`Panel`（卡片/详情/表单外框）、进度条（上传进度）；全站 `Hotkeys` 仅前台启用，避免与后台输入框冲突。
- 首页：Hero（游戏名、简介、三平台下载按钮、版本/大小）+ 地图精选（前 6 张卡片）+ 联系信息区。
- `/maps`：封面、名称、作者、人数、版本、大小、下载按钮；`/maps/[slug]` 显示完整介绍与 OSS 下载链接。
- 数据读取使用 `revalidate = 60`；后台写操作后 `revalidatePath` 对应语言页面。
- 上线前替换现有英文硬编码文案；移动端 390px 宽验收。

## 管理后台

- 登录：`/admin/login` 提交密码，Server Action 用 `crypto.timingSafeEqual`（配合 scrypt 哈希）校验；成功写 `ow3_admin` cookie（HMAC-SHA256、HttpOnly、Secure、SameSite=Strict、Path=/、7 天）。简单内存限流防爆破。
- 保护：`app/admin/(protected)/layout.tsx` 中 `await requireAdmin()`，失败 `redirect("/admin/login")`；不在 proxy 中查库。
- 功能页：
  - 下载管理：平台、版本、格式、大小、URL/OSS 上传、启用、排序。
  - 地图管理：列表 + 编辑；语言标签页维护名称/介绍；封面上传、w3x 上传；发布/草稿；排序。
  - 联系信息：邮箱、QQ 群、微信、GitHub、Discord、备注。
  - 语言管理：启用/停用、排序（只影响前台展示）。
- 表单提交使用 Server Action + `useActionState`；服务端校验长度、URL 协议、扩展名白名单（`.w3x/.jpg/.jpeg/.png/.webp`）。
- 上传流程：`POST /api/admin/oss-sign`（校验会话）→ `ali-oss` 的 `signatureUrl(key, { method: "PUT", expires: 600 })` → 浏览器 PUT 直传 → 表单提交 `key/url/size` → 服务端 HEAD 校验后落库。`ali-oss` 需在 `next.config.ts` 配 `serverExternalPackages: ["ali-oss"]`。

## 实施步骤

1. **基础**：`web/` 执行 `npm install`；新增 `ali-oss`；更新 `next.config.ts`（`serverExternalPackages`、OSS 图片 `remotePatterns`）；新增 `.env.example`；`.gitignore` 忽略 `web/data/`、`.env*`。
2. **数据库**：`lib/db/*` 单例与 schema；`scripts/migrate.mjs`、`scripts/seed.mjs`；先跑通建表与 seed。
3. **多语言骨架**：`i18n/*` 词典、`proxy.ts` 重定向前缀、语言切换组件；把现有英文文案迁入 `en.ts`。
4. **前台壳与首页**：根 layout 拆分、`AppShell`、新首页（游戏介绍 + 下载 + 精选地图）、响应式样式。
5. **地图列表与详情**：`/maps`、`/maps/[slug]`，接入 `map_translations` 与回退链。
6. **后台鉴权**：登录页、cookie 签发/校验、protected layout、登出。
7. **后台 CRUD**：下载地址、联系信息、语言配置、地图与多语言文本。
8. **OSS 上传**：签名 API、`UploadField`（进度/大小限制）、HEAD 校验、落库与失效清理。
9. **SEO 与收尾**：metadata/hreflang、sitemap/robots、README（npm 与部署说明）、`/download/[os]` 改为 DB 优先。
10. **验证与修复**：typecheck、build、手测清单。

## 风险与边界

- SQLite 仅支持单进程写入；WAL + `busy_timeout=5000`，部署保持单实例，并加 `data/` 定期备份。
- 服务器需 Node ≥24（`node:sqlite` 稳定）；`next build` 期间避免访问真实 DB（相关页面 `dynamic = "force-dynamic"` 或用 DB 存在性守卫）。
- OSS Bucket 需配置 CORS 允许站点域名 PUT；预签名 TTL 10 分钟；object key 用随机 UUID + 白名单扩展名，避免覆盖。
- 大文件直传不经过 Node，但失败重试需在上传组件中提示；避免同一文件并发提交。
- 旧 `web/lib/github.ts` 保留为 star 数与下载兜底；`/download/[os]` 改造后行为不变。
- 使用 npm 后 `web/pnpm-lock.yaml` 将失效，README 与部署命令统一为 npm（如有 Vercel 旧部署需同步调整）。
