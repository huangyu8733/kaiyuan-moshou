## 侧车整体不生效的根因与修复（关键）
- **现象**：实机验证发现——英雄技能 tooltip 全英文、物品需求（"装备需要什么"）非中文、进入 DotA 后左侧菜单是西班牙语、地图选择界面描述还是葡语。即整张地图侧车（wts/text/objects 全覆盖）一个字都没生效。
- **逐层排查已排除**：① install.files 含侧车（readInstallDir/collectMaps、devBoot、nativeInstall 三条路径都收集 `.zhCN.json`）；② `pathOfMapFile` 引用反查成立、mapPath 正确传入 `startGame`；③ `LooseFilesDataSource`/`normalizeMpqPath` 键归一化一致（候选1 = `Maps\hhkj\DotA AI v6.90G PT-BR v4.1.w3x.zhCN.json` 必命中）；④ 用真实侧车 Node 验证 `loadMapLanguage` 必找到并解析（A0BK→"麻痹之咬"等中文正常）。
- **真因**：`src/i18n/mapLanguage.ts` 的 `live()` 旧逻辑 `return active && currentLocale() === "zhCN" ? active : null;`——把"应用 UI 语言"当成了开关。用户装 `Warcraft III zhCN`（游戏数据本就中文，故"学习"等引擎文字是中文），但 `currentLocale()` 在会话里不是 zhCN（早期测试切过英文 / URL 带过 `?lang=enUS` 写进了 localStorage），于是整张侧车被 `live()` 静默关掉——菜单西语、技能英文、物品非中文、描述葡语全部吻合。
- **修复**：`live()` 改为 `return active;`（侧车文件 `*.zhCN.json` 的 `locale:"zhCN"` 字段本身就是语言范围，存在即代表玩家要中文），删除多余的 `currentLocale()` 闸门、移除未用的 `import { currentLocale }`。已 `tsc --noEmit` 通过。
- **效果**：`applyMapObjectLanguage`(技能/物品/单位名与 tip/ubertip)、`mapDisplayText`(脚本上屏行如"第一滴血")、`localizedMapInfo` 在侧车加载后即生效，不再受应用界面语言影响。地图选择界面的"描述"葡语属次要生成器缺口（sidecar 的 `text` 表未含该原始行），不在本修范围。
- **验证方式**：dev server 走 HMR 自动生效，用户刷新页面重进 DotA 即可确认；若仍非中文，需看 `loadMapLanguage` 是否真的加载到（控制台 `[i18n] map language: ...` 日志）。

## 第二轮：仍英文 → 侧车"根本没加载"的加固（含学习面板通道缺口）
- **复核结论**：用 `.sim-build` 编译产物 + 真实侧车跑真链路，`loadMapLanguage`→`setMapLanguage`→`applyMapObjectLanguage` 完全正确（10 字段覆盖、A0BK→麻痹之咬、mdpb→美杜莎之石）。故 `live()` 不是唯一问题——**运行时 `active` 为 null**（侧车没被加载）才能解释"技能名/技能说明/合成所需物品名"三个症状同时存在。
- **发现的新缺口（真实且必现）**：DotA 学习面板读的是 `AbilityDef.researchTip` / `researchUberTip`（w3a 的 `Researchtip`/`Researchubertip`），而侧车只写 `tips`/`uberTips`——**这两个字段侧车从未覆盖**，所以"学习 XXX"与悬停说明会保留地图原语言。已在 `applyMapObjectLanguage` 补：有中文 `name` 时 `researchTip = "<name> - [|cffffcc00等级 %d|r]"`（页面自己替换 `%d`），有中文 `uberTips` 时清空 `researchUberTip` 让学习页回落到 `abilityDesc`（按等级的中文正文）。
- **加载层加固**（`src/i18n/mapLanguage.ts`）：① `installReader` 不再仅凭 `exists()` 判定——`exists` 说没有也再试读一次（松散层/分层数据源的 `exists` 可能答错，文件其实可读）；② 新增 `findMapLanguageByName(read, list, mapName)`，路径拼写不一致或用例/分隔符对不上时按**文件名**在 `install.list()` 里兜底；③ `loadMapLanguage` 找不到时**打印 `[i18n] no map language file beside ... — tried ...`**（原来完全静默）；④ `applyMapObjectLanguage` 打印 matched/missing，匹配 0 条时 `console.warn`。
- **幂等 + 二次应用**（`src/render/mapViewer.ts` `beginMatch`）：覆盖函数开头先 `undo` 还原再覆盖（可重复调用）；`beginMatch` 在真正开局前再调一次，避免加载期时机错过。
- **`main.ts`**：`pathOfMapFile` 增加按文件名反查兜底（引用相等失败时）；`startGame` 在按路径找不到侧车时用 `findMapLanguageByName`；新增诊断 `window.warcraft-open.mapLanguage`（返回 `{live, wts, text, abilities, items...}`，控制台一行即可判断侧车有没有加载）。

## 第三轮：侧车其实早已生效 —— 真凶是"描述里残留英文物品/技能名"
- **实证推翻前两轮猜测**：用仓库自带 Electron（`node_modules/.bin/electron`，需 `env -u ELECTRON_RUN_AS_NODE` + `--no-sandbox`，隐藏窗口截图是黑的，要 `show:true`）跑 `?dev&map=DotA AI v6.90G`，控制台拿到 `[i18n] map language: ... 13983 object field(s) overridden (5653 matched)`，且游戏内物品提示正文已是中文。**侧车加载与覆盖都正常**，之前的 `live()`/安装路径猜测不是遗留英文的原因。
- **真凶**：DotA 没有 war3map.w3u/w3t，英雄/物品/技能的一切文本都在 `.w3x` 内的 `Units\ItemStrings.txt`、`Units\CampaignUnitStrings.txt`、`Units\CampaignAbilityStrings.txt`（`Name=`/`Ubertip=` 字段）。侧车把这些**句子**翻了，但句子里嵌的**英文物品名/技能名**没翻：`需要:|nMaelstrom - 2800 (Enchanted Artifacts)`、`可学习 Overpower, Earthshock ... |c00ff8000Enrage|r`。
- **修法（新工具）**：`tools/map-zh-patch/apply-names.cjs <sidecar.json>...`
  - 从地图自带的三个字符串表取 rawcode→英文名，与侧车同 rawcode 的中文名配对（另有 `tools/dota-ability-zh.json` 兜底）；只做**物品名+技能名**，不动单位/英雄专名（避免把背景故事里的 Mortred 换成称号）。
  - 关键坑：`|nMaelstrom`、`|c00ff8000Enrage|r` 里名字前面是标记的字母/数字，单靠"前面不是字母"的断言会全部漏掉 → 先把 `|cXXXXXXXX`/`|n`/`|r` 遮成 `\u0001<idx>\u0001`，替换后再还原。
  - 顺便把 `(Enchanted Artifacts)` 这类**括号里的商店名**单独用单位名表替换（只作用于括号内）。
  - 配对表同时写进侧车 `names` 字段（供后续/其他地图复用）。
- **结果**：6.90G 915 对/678 字符串重写；6.83d 523 对/588 字符串。实机截图确认「碎颅锤」提示变为 `需要: 标枪 - 1500 / 巨人力量腰带 - 450 / 配方 - 750`、`重击 不与其他被动晕眩技能叠加`；英雄卡变为「可学习 超强力量, 大地震击, 怒意狂击 和 激怒」。
- **注意**：`map-zh-extract.cjs` 重新生成侧车后会把描述刷回英文名，**必须再跑一次 `apply-names.cjs`**。备份在 `/tmp/map-names-backup/`。
- 仍残留：少数配方行括号内的商店名（仅 6.90G 有 35 个商店名，部分不在单位表中）、英雄专名（Mortred/Davion 等，属正常）。

  - 顺序：① 截断生成器把数组拼成 `"a","b"` 的残渣（英雄卡尾部会拖别英雄的技能表，6.90G 15 处 / 6.83d 5 处）；② 删译文里夹带的葡语注记（`（deixando-os）` 等 16 处）；③ 去掉中文后粘着的半截拉丁词尾（`恢复ção`→`恢复`）；④ 词组→单词替换（颜色码 `|cXXXXXXXX`/`|n`/`|r` 先遮成 `\u0001N\u0001` 再还原，否则 `|nMaelstrom` 这类边界判断全漏）；⑤ 技能/科技文本里的引擎占位符 `<AHav,DataA1>` → 「若干」（客户端不解析，原样显示就是尖括号）；⑥ 中文间空格、`中文-de-中文` 之类连接词、机翻连字符（`不死-生物`）收干净。
  - 幂等：连跑两次内容不变（md5 相同）。
- **结果**：6.90G units 残留仅 2 处（`-quero` 聊天命令、`ESC` 键名，故意保留）、items 仅邮箱地址；6.83d units 62 处（多为冷门单位 tip 里的物品/技能名）。
- **关键判断**：单字母残留（`建造 F 王者祭坛`）是 **热键字母**，不是未翻译文本，不能动。
- **enUS 目录的侧车**：两张 .w3x 在两个安装里 md5 完全相同，enUS 侧车内容却是「中文正文 + 英文技能名」，且游戏只用 `Warcraft III`→zhCN 软链，故直接把 zhCN 侧车覆盖过去，两份 md5 一致。
- **工具链**：`map-zh-extract.cjs` 重新生成侧车后，必须依次再跑 `apply-names.cjs` → `apply-glossary.cjs`（否则名字和专名会刷回英文）。备份：`/tmp/map-names-backup/`（apply-names 前）、`/tmp/glossary-backup/`（本轮前）。
- **仍未做**：abilities 里 65 种（6.90G）/ 63 种（6.83d）英文仍在——主要是 63 个「阿哈利姆神杖升级」条目里的英文技能代号（Undermine、Headshots 等），这些条目本身无中文名、地图字符串表里也查不到对应 rawcode，需人工确定英雄才能对译。
